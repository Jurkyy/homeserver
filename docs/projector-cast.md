# Projector / Browser Cast (mediacast)

Send any URL from your Android phone's Firefox share menu and it opens
on the projector. No keyboard on the projector screen, no Spotify-style
"app must be the controller" — just share, watch.

## Pipeline

```
Android Firefox  → share menu → HTTP Shortcuts  → POST :8765/cast
                                                       │
                                       (mediacast container, FastAPI)
                                       checks bearer token + URL
                                                       │
                                            forwards to :8766/open
                                                       │
                                       (mediacast-host, systemd --user)
                                       xset dpms force on  → projector wakes
                                       firefox-esr --new-tab <url>
                                       wmctrl -a Firefox   → raise/focus
```

The auto-logged-in Xfce session on tty1 owns the HDMI. Firefox is
pre-launched at session start (autostart .desktop) so the cast is
instant. uBlock Origin and SponsorBlock come pre-installed via a
system-wide Mozilla policies.json.

## Phone setup (one time, ~3 min)

1. Install **HTTP Shortcuts** — Android, F-Droid or Play Store. Free
   and open-source: <https://http-shortcuts.rmy.ch/>.
2. Open it → **+** (new shortcut) → **Empty shortcut**.
3. Fill in:
   - **Name**: `Cast to projector`
   - **Method**: `POST`
   - **URL**: `http://<homeserver-lan-ip>:8765/cast` (or the Tailscale
     IP if you want it to work off the home LAN too)
   - **Body type** → **Custom text** → content:
     ```json
     {"url": "{{shared_text}}"}
     ```
   - **Request Headers** → add two:
     - `Authorization` → `Bearer <your MEDIACAST_TOKEN>` (get it from
       `~/homeserver/.env` on the server — the value generated by
       bootstrap)
     - `Content-Type` → `application/json`
4. **Trigger & Execution Settings** → check **Add to share menu**.
   Optional: enable a toast on success/failure.
5. Save.

Now in Firefox Android: share button (top right or in URL bar menu) →
**Cast to projector** → URL fires at the server, projector wakes,
video plays.

## Audio

Browser audio (YouTube, streaming sites) goes through PipeWire/PulseAudio
to the Focusrite Scarlett 2i2 — the same output librespot uses for
Spotify Connect. **One at a time, please.** librespot opens the ALSA
device exclusively (`--backend alsa --device plughw:CARD=USB,DEV=0`),
so if Spotify is actively playing, browser audio will fail to open the
device (and vice versa). Stop Spotify before casting, or vice versa.

If this becomes painful, swap librespot's backend to
`--backend pulseaudio` in `docker-compose.yml` so both share the device
via the PipeWire/Pulse mixer.

## Testing

From your laptop on the LAN (or Tailscale):

```bash
curl -X POST http://<homeserver-lan-ip>:8765/cast \
    -H "Authorization: Bearer $(grep ^MEDIACAST_TOKEN= ~/homeserver/.env | cut -d= -f2)" \
    -H 'Content-Type: application/json' \
    -d '{"url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"}'
```

Expect: `{"status":"ok"}`, projector wakes within a couple of seconds,
video starts playing in Firefox.

Health checks:

```bash
curl http://<homeserver-lan-ip>:8765/health           # container
curl http://localhost:8766/health                     # host helper (ssh'd in)
```

## Idle / wake behaviour

- DPMS blanks the HDMI output after 10 min of no input (set in
  `~/.xprofile` by `install_projector_session`).
- Most projectors auto-sleep on no-signal after their own timeout
  (1–10 min depending on model).
- A cast request runs `xset dpms force on` before launching Firefox,
  which wakes the HDMI; the projector then powers on automatically
  when it sees signal return. If your projector doesn't auto-wake on
  HDMI signal, install `cec-utils` and add a `cec-client` "on 0" call
  to the wake path (or use a Pulse-Eight USB-CEC adapter — see
  `docs/smart-home-hardware-guide.md`).

## Troubleshooting

| Symptom | Check |
|---|---|
| `401 bad token` | The bearer header doesn't match `MEDIACAST_TOKEN` in `.env`. Re-copy from `grep ^MEDIACAST_TOKEN ~/homeserver/.env`. |
| `502 host helper unreachable` | Host helper isn't running. `systemctl --user status mediacast-host` (as the bootstrap user). Check logs: `journalctl --user -u mediacast-host -e`. |
| `502 firefox failed` | Firefox isn't running or the binary path is wrong. Verify `pgrep -a firefox-esr` returns something. If not, the autostart .desktop didn't fire — log in graphically once to bootstrap it. |
| Cast says OK, projector stays dark | The DPMS wake worked but the projector lost signal sync. Confirm with `xset q` (should show `Monitor is On`). If yes, it's the projector — check its no-signal timer and HDMI cable. |
| New tab opens but URL doesn't play | Probably a paywall/login screen. Use the attached USB keyboard/mouse to sign in once; the cookie persists in the profile. |
| uBlock / SponsorBlock not installed | Policies are applied on first Firefox launch. If Firefox was already running when policies were installed, restart it: `pkill firefox-esr; firefox-esr &`. |
| 8765 unreachable from LAN | NordVPN allowlist usually covers LAN already (`nordvpn allowlist`). If your LAN isn't a /24 or /16, add it manually: `sudo nordvpn allowlist add subnet 192.168.x.0/24`. |

## Security notes

`POST /cast` opens an arbitrary URL in an auto-logged-in browser
session. The trust boundary is `MEDIACAST_TOKEN`:

- Generated as 32 random bytes by bootstrap; never commit `.env`.
- Both hops re-check the token. The host helper binds 0.0.0.0 (the
  docker bridge gateway isn't a stable loopback-equivalent for compose
  networks), so it's reachable from the LAN too — the token is what
  keeps that safe.
- The URL is validated to be `http://` or `https://` only — no
  `file://`, `javascript:`, or `data:` URIs.
- The endpoint is **not** proxied through Caddy and **not** exposed on
  the public internet. LAN + Tailscale only.
